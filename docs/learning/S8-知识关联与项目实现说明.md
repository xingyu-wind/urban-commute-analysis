# S8｜用户权限、安全与运行管理：知识关联与实现说明

本阶段使用 Spring Security 6.5、BCrypt、Servlet 会话、CSRF、Spring JDBC / MySQL 8.4、Flyway V6、Vue 3、Python 既有 S7 适配器及 Playwright Chromium。职责是把现有只读分析与受控管理区连接起来，而非替换 ETL、数仓或预测发布引擎。

## 一条实际调用链

```text
OperationsPanel.vue → GET auth/csrf → POST auth/login
→ Spring Security 登录过滤器 → UserDetailsService 参数化查询 app_user
→ BCrypt 校验 → 更换会话 ID → HttpOnly 会话 Cookie
→ GET auth/me → ADMIN / READER 身份

ADMIN 上传 → SecurityFilterChain（会话 + CSRF + 角色）
→ OperationsController.upload → Operations.upload
→ UUID 隔离文件 → AdapterWorker.run（固定本机 Python 脚本）
→ s8_adapter_bridge.execute → S7 inspect_file → PROPOSED
→ 管理员完整 review + 精确提案哈希 → S7 confirm
→ managed_import 保存确认人、UTC 时间、配置和 SHA
→ execute → managed_job 唯一约束 → RUNNING
→ S7 convert + suitability → 隔离规范输入 → SUCCEEDED / FAILED
→ security_audit → Vue 状态与追溯
```

## 为什么要这样设计

认证回答“是谁”，授权回答“能做什么”。Vue 隐藏上传按钮仅改善操作体验；真正的管理拒绝发生在 Java 过滤链，甚至不会进入文件保存方法。未登录返回 401，已登录但角色或 CSRF 不满足返回 403。CSRF 过滤器比请求用户包装器更早运行，所以错误处理从 SecurityContext 读取身份，不能错误地用尚未包装的 `getRemoteUser()` 判断。

浏览器经 Vite 同源代理访问本地 Java，因而无须开放 CORS。会话 Cookie 设置 HttpOnly 和 SameSite=Strict，写请求还必须带服务端 CSRF token；登录后会话 ID 和 CSRF 均更新，退出清除会话。登录审计写入失败会撤销刚建立的认证；退出审计失败会告警，但不能阻止会话失效。回环 HTTP 的 Secure=false 是开发环境策略，未来经授权的 HTTPS 部署必须设置 true。没有明文密码、默认管理员、JWT 持久化或 URL 会话追踪。

上传名称从不决定实际路径。原件放 UUID 目录里的固定 `input.csv/json`，由 S7 全量解析，大小、行数和格式有界。推荐不是授权：确认请求必须完整提供语义、许可和用途，服务器记录会话操作者；执行还要重新核验文件与映射哈希、权利和适用性。S8 没有另写一套速度转拥堵指数算法，也没有把速度研究输入直接写入既有交通观测表。

任务管理只开放确实可安全重试的 S8 导入校验。每个上传唯一一个任务，重试以 `FAILED → RUNNING` 的数据库比较更新抢占，最多三次。成功任务或并发重复请求返回 409；失败删除部分规范输出，保留确认过的输入。ETL/Hive/ML 展示原阶段任务表及批次、版本，仍经原受控 CLI 执行，不接受 Web 端任意命令或发布指针修改。硬退出遗留 RUNNING 不自动接管，以免把不确定状态当成失败重试。

## 数据库如何留下可复核证据

`managed_import` 保存文件 SHA、原建议、完整已确认配置、配置 SHA、确认人和时间。`managed_job` 以 `import_id` 唯一约束绑定任务，记录尝试次数、操作者、输入/映射/输出版本、适用性与安全失败码。`security_audit` 用动作、对象 ID、UTC 时间、结果及 request ID 串起上传失败、确认、执行、重试、登录和越权。审计不保存密码、token、Cookie 或原始拒绝片段。旧 CLI 任务缺少 Web 操作者的历史事实保留，不补造操作人。

实测通过了合法 CSV / JSON、路径与格式攻击、清理、缺失与陈旧 CSRF、退出后的旧 Cookie 重放、真实空闲过期、读角色越权、未确认/改文件/缺许可/样本过短、失败修复重试与并发 200/409。测试独立回读 MySQL 和文件系统，确认观测表及两个发布指针未污染；再由 Chromium 真实登录、确认、执行及窄屏检查验证 UI。测试均使用可再分发合成数据，不证明真实交通预测能力。

## 答辩时可以这样回答

“我用 Spring Security 做服务端会话认证，数据库存 BCrypt 强哈希，管理员和只读用户在服务端按路径授权。前端通过同源代理访问，写操作需要 CSRF token，登录会换会话，退出和超时使旧会话失效。上传文件由服务器分配隔离目录，再调用原 S7 适配器分析。字段建议必须经管理员完整确认，文件和映射哈希都不匹配时不能执行。导入还会检查数据权利与任务适用性，不会把任意速度文件直接发布为拥堵预测。运行管理复用原 ETL/Hive/ML 记录，只对独立校验任务做有界重试。数据库约束和状态比较更新防止重复执行，审计可追踪操作者、版本与请求。我用真实 MySQL、HTTP、文件系统和 Chromium 做了安全负测，再交由总规划师独立验收。”

当前限制：只有回环开发环境；未实现公网登录限速、账号自助管理、跨节点会话、文件自动保留期和硬退出任务自动接管。S7 的真实数据许可/下载阻塞没有被 S8 豁免或改写。具体命令、CI 与真实证据见 [S8 阶段报告](../stage-reports/S8.md) 和 [运行指南](../guides/s8-operations.md)。
