# S9 知识关联与项目实现说明

## 一、Spring Security：路由允许与角色授权是两道门

`backend/.../security/SecurityConfig.java` 用精确路径和HttpMethod列出可达接口，再由ADMIN/READER控制操作权限，末尾denyAll。原permitAll使以后新增Controller自动继承匿名访问；只补前端隐藏按钮无法修复这个服务端问题。当前未知路径直接拒绝404，不转发MVC；旧只读路由错误方法直接405并保留Allow，统一ApiResponse、requestId与审计不变。

调用链：浏览器获取CSRF→POST登录→BCrypt校验数据库用户→更换会话ID→每次管理请求校验CSRF和角色→Operations校验UUID/文件/映射/状态→固定Python适配器。登录审计失败撤销认证，退出审计失败仍须使会话失效。不能把“有token”理解为“有ADMIN权限”，安全矩阵特意让低权限请求带有效token。

答辩：怎样证明新接口不会自动开放？`DefaultDenialIntegrationTest` 在真实嵌入式HTTP服务器注册未来Controller，18次请求返回404且方法计数0；`scripts/s8_checks.py` 对实际JAR使用匿名/READER/ADMIN请求，前后查询真实MySQL业务表与私有目录，拒绝时无业务写入。拒绝所需安全审计允许追加，不与业务写入混淆。原404/405测试仍保留原预期。

## 二、数据契约：单位、目标和许可决定能走到哪里

`ml/data_adapter.py` 分析字段并推荐映射；confirm记录人工审查、操作者和哈希，convert保留来源/单位/时区/目标，suitability按采样周期与预测窗口判断适用性。`ml/domain_evaluation.py` 使用过去特征、滚动起点、验证选模、独立测试和源域冻结迁移。来源台账由 `scripts/s9_sources.py` 重查公开元数据与本地校验和，只输出聚合证据。

两条实际契约不同：S8→traffic-series-v1是速度/流量研究输入；S5→MySQL观测→S6准入→S7 forecast是CITY每日0–10拥堵指数发布。Hive ADS独立经对账发布warehouse_current；S7用MySQL准入观测，不假装每次消费新Hive输出。`ml/forecast.py` 发布重新准入并可信重训重算，不反序列化不可信joblib，最后事务切换prediction_current。两指针职责不同。

答辩：为什么有CSV却没真实准确率？本地片段不完整，具体版本的单位/时区/零值和上游权利未核实。网页200、代码MIT、存储库CC声明不能替代完整数据来源核查。真实训练必须停止并保留解除条件，合成样例只证明流程。真实单集、跨时间、跨域结论分别记录，不用合成误差声称泛化。

## 三、部署、可观测性与隔离恢复

`scripts/s9_runtime.py` 启动Java并等待健康，再启动已构建Vue dist的Vite preview同源代理；保持回环、记录本次日志、只停止持有的子进程。`frontend/vite.config.ts` 的preview与dev共用代理目标校验。MySQL/HDFS归已有服务管理，脚本不接管。实际Hadoop3.4.1/Hive4.1.0由既有CI隔离容器计算，本机不以Mock补位。

`scripts/s3_database.py --with-restore-target` 产生两个独立随机库和单库账号；`scripts/s9_release_checks.py` 先核对真实实例身份与空目标，只备份当前合成库，mysqldump输出留在忽略私有目录。全表规范JSON逐行排序→SHA256→源/恢复比对→Flyway重新校验→API data相等，包含任务、模型结果和current指针；再次核查源库没有变化。

答辩：为何比较行数还不够？同样七条预测也可能有一条数值被改动。内容哈希发现数据差异，指针/API比对发现恢复了明细却没恢复可见版本；恢复启动验证迁移历史与真实查询，而不仅验证SQL文件能被生成。本次不备份上传/权重/HDFS目录，不能据此承诺整机灾备或RPO/RTO。
