# S4：知识关联与项目实现说明

本阶段把 S3 中存进 MySQL 的观测转成可操作的交通分析工作台。用户选择城市和 UTC 时间范围后，Java 在线计算城市 KPI、历史趋势、区域对比、路段排名；Vue 和 ECharts 负责显示与交互。当前演示使用 `synthetic_test`，不能介绍成真实城市采集，更没有通勤人数预测。

## 1. 技术如何连起来

Spring Boot 负责 HTTP 路由、JSON 和统一异常。Spring JDBC 用参数绑定查询 MySQL 8.4，保留已有 Flyway V1/V2 管理表结构。Vue 3 的响应式状态连接城市选择、日期、趋势粒度、区域和分页；TypeScript 描述返回类型，运行时校验拒绝不合约定的 JSON。ECharts 将这些已验证的响应绘成趋势、柱图和经纬度点位。Vite 提供本机开发代理与生产构建。

五张表各有职责：`dataset_registry` 登记来源；`city`、`region`、`road_segment` 描述对象和归属；`traffic_observation` 保存目标层级、观测时间、速度和拥堵指数。同一个数据库既能存城市统计，也能存区域和道路观测，但查询必须按 `target_type` 隔离，不能把三个层级相加。

实际调用链是：

```text
城市/日期/区域筛选
  → TrafficDashboard.vue 组织请求
  → api/traffic.ts 调用 /api/v1/traffic/* 并校验 JSON
  → TrafficController → TrafficQuery 验证参数
  → TrafficRepository 绑定参数、在一致快照内查询 MySQL
  → Traffic DTO + ApiResponse + 来源/截至时间
  → Vue 更新 KPI、ECharts、地图与排名
```

前端不连接数据库，也没有写死 KPI。数据库中一条 CITY 速度从42改成60后，城市平均速度从36变成42；刷新页面同样出现42，恢复该记录后回到36。这是证明真实数据链路的演示重点。

## 2. 统计与数据库知识

KPI 使用观测样本的算术平均：速度之和除以样本数，单位 km/h；拥堵指数同样平均，取值0–10。样本数是数据库观测行数，不是独立车辆数。测试窗口中城市只有3条样本，区域和道路另有6条，城市分母仍然是3。

时间采用 UTC 半开区间 `[from,to)`：包含开始，不包含结束，连续时间窗口不会重复计入边界记录。小时、日期也按 UTC 分桶；有偏移的请求先转为 UTC。缺失桶用 N=0、指标=null 表示，图表断开；零速度则是真正观测为零，二者不能混淆。

每次只统计一个数据集，并返回来源、数据集 ID 和最大观测时间。预测、mock 和 simulation 不参与历史统计。登记为授权来源也不代表程序已经核实外部授权。SQL 值全部绑定，路段搜索按字面子串处理；页数、大小、时间跨度都有上限，稳定排序保证同分路段也有确定顺序。

单个接口的多条 SQL 放进只读 repeatable-read 事务，避免一次响应中的总数、列表和截至时间来自不同提交。四个接口各自独立，不宣称它们是同一个跨 HTTP 事务。

## 3. 前端与地图知识

Vue 监听筛选变化并重新请求四个接口；每轮请求有递增版本号。只有最新一轮可以写入界面，旧请求晚到也不会覆盖新城市。加载和失败时清除旧统计，避免把旧数字误认为当前筛选结果。

趋势图用双轴区分 km/h 和0–10指数，可悬停、缩放、查看数据表；柱图点击区域后更新路段筛选。路段支持关键词、分页和区域清除。比赛大屏是同一套数据的视口展示模式，窄屏改为单列，并提供加载、无数据、错误、稀疏样本提示。

地图采用离线 WGS84 区域点位视图，只绘制数据库提供的完整合法坐标。缺少坐标的区域保留文字说明；没有道路几何就不画道路。合成点位只验证渲染和交互，不是城市实测位置。此方案没有在线瓦片、商业密钥或外部地图账号。

## 5. 向老师讲述的顺序

先说问题：“我需要从数据库回答某城市在某段时间内速度如何、哪些区域更拥堵、哪些路段值得关注。”然后选合成演示城市和样本时段，介绍3条 CITY 样本为何得到36 km/h和指数5。

接着操作趋势粒度、点选东区、查看路段A，说明三个层级分别统计、地图只使用登记坐标。展示空时段的横杠，说明没有把缺失伪装成零。再展示受控数据库修改证据，解释数字经 MySQL→Java API→Vue→ECharts 更新。

最后打开独立 SQL、契约与真实浏览器证据，说明验证覆盖正确值、空值、非法参数、数据库不可用和 S2/S3 回归。收尾明确：S4 完成统计与展示，数据为合成测试；ETL、Hadoop/Hive、机器学习属于后续阶段，本次没有开发或宣称完成。
