# S5 知识关联与项目实现说明

S5 的职责是把来源可解释的原始文件，变成系统能够安全统计的交通观测。当前使用自主生成的 synthetic_test 数据，完整验证工程链路，不声称已采集真实交通。公开来源核查记录在 `data-pipeline/sources.json`；来源登记是审计信息，不能代替第三方授权证明。

## 主要技术及职责

| 技术 | 在本项目的实际职责 |
|---|---|
| Python3.11、csv/json | 读取原始文件，按配置映射列名，检查字段、类型、空间归属，输出合格数据和拒绝明细 |
| datetime、Decimal、SHA-256 | 统一 UTC 与毫秒精度，精确换算单位和四舍五入，固定原始文件与配置身份 |
| PyMySQL、InnoDB事务、命名锁 | 参数化写入、逐条内容比对、原子提交、并发隔离及失败重试 |
| MySQL8.4、Flyway V3 | 保留原有观测模型，增加来源快照、导入批次、质量拒绝和逐条血缘表 |
| Java21、Spring Boot、JDBC | 复用 S4 统计 API，从实际数据库读取分层样本算术均值 |
| Vue3、TypeScript、ECharts | 复用 S4 工作台和大屏，显示导入后的真实统计结果，保留空值和来源提示 |
| pytest、JUnit、Playwright、GitHub Actions | 验证清洗、真实 MySQL、进程中断恢复、API契约与实际 Chromium 页面变化 |

## 模块调用和完整数据流

操作者提供 CSV/JSON、配置文件、数据版本和 batch ID。`python -m commute_etl` 先调用 clean.py，核对来源状态和目录，再将输入列映射为统一字段。时间必须明确偏移，统一转换为 UTC；速度统一 km/h，拥堵统一0–10。无法可靠解释的单位、缺失字段、越界值和跨城错误关联都会进入拒绝明细，不会被改成零。

清洗结果写入 normalized.csv/json，连同 quality.json、rejections.json 和 source.json 保存。这些文件说明“哪些行通过了清洗”。加上 --load 后才会调用 store.py 连接由 S3 工具创建的新隔离数据库，并核查真实库、账号、服务器 UUID。

导入器先登记 RUNNING 批次，再在一个事务内写观测和血缘。已有唯一键同值则记为已存在；异值则记录冲突，整批回滚，不覆盖旧数据。观测、血缘、最终数量及 SUCCEEDED 状态一起提交。进程崩溃时 MySQL 回滚未提交事务，批次仍能显示 RUNNING；重试取得同一数据集锁后安全重放。成功批次再次执行也不会产生新观测。

随后浏览器仍然调用 S4 的 `/api/v1/traffic/summary|series|regions|roads`。Java 查询 MySQL，Vue 校验响应，ECharts 更新趋势、区域图与大屏。CITY、REGION、ROAD 和不同 dataset_id 独立统计，缺失观测显示空值，不参与均值。道路指标不能直接当作城市指标或通勤人数。

## 与 S3、S4、S6 的关系

S3 建立数据库模型、Flyway和安全测试隔离，S5沿用这些约束并追加V3审计表。S4已经实现统计API与图表，S5补齐原始文件进入数据库的上游，使界面变化来自Python实际导入。S6可以复用标准化CSV/JSON及数据字典设计Hadoop/Hive离线层，但必须继续保留数据集、层级、UTC、缺失和来源语义。S5没有实施Hive，也没有提前进入S6。

## 向老师说明实现过程

可以这样讲：“我先解决数据能不能用、字段是什么意思，再解决如何稳定入库。程序将原始文件的每条记录校验并标准化，错误行有明确原因，合格行有文件和配置哈希。入库时，同一观测不会重复，冲突不会覆盖；即使导入过程中程序退出，也能检查批次状态并安全重跑。最后沿用Java统计接口和Vue图表，用实际导入前后的变化证明各模块已经接通。”

演示时先显示合成城市无观测，运行CSV导入后，CITY有2条，速度为(36+72)/2=54 km/h、拥堵为3；再运行JSON导入，仅新增速度12、拥堵9的一条CITY观测，原有9条跨层级/城市记录去重，城市均速变为(36+72+12)/3=40、拥堵变为5，样本数为3。区域均速36、道路均速18各自独立。再次导入保持不变，再展示质量报告、批次计数和中断恢复测试，就能解释“可运行、可重复、可追溯”的具体含义。

工程边界也应明确说明：目前是小批量离线导入，来源为合成测试，不代表真实城市交通、真实地理采集或个人通勤预测；生产库部署、大规模流式处理和后续Hive工作尚未实施。
