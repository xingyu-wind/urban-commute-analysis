# S6｜知识关联与项目实现说明

本阶段把已经通过 S5 的标准化观测，接成“离线计算后发布给分析页面”的链路。Hadoop/Hive 与 Spring Boot 分别使用独立运行环境：数仓使用 Java17，后端继续使用 Java21。所有演示来源都明确标记为 synthetic_test 合成测试，样本数指观测记录条数，不能解释成车辆或通勤人数。

## 这些技术在项目里各做什么

**Hadoop** 是大数据基础设施的项目集合。本阶段实际使用其中的 HDFS 存储接口，并通过 Hive 和 Tez 执行离线 SQL。**HDFS** 保存带校验信息的标准化来源、分区文件及导出结果；它不直接承担网页接口。我们的验证会真正启动 NameNode 和 DataNode，上传文件、列出目录，再下载文件核对 SHA-256。

**Hive** 把 HDFS 中的文件映射成表，让离线任务使用 SQL。**Metastore** 保存表结构、位置和分区元数据，本次隔离验证使用独立 Derby。**Tez** 执行 Hive 生成的计算任务；当前是单节点 local mode，足以证明真实存储和 SQL 链路，不代表已经验证多节点吞吐性能。**Beeline** 是提交 Hive SQL 和读取执行结果的客户端。

四层数仓各有职责：ODS 保留标准化来源及批次；DWD 保留统一 UTC 的去重明细；DWS 保存小时维度的数量、总和和时间覆盖；ADS 生成页面与后续特征消费能够使用的小时、日和窗口结果。ODS 到 ADS 的计算位于 `bigdata/sql/warehouse.hql`，实际由 Hive 执行；Python 的独立计算只用于验证结果。

## 数据怎样进入并展示出来

```text
S5 normalized.json + source.json + batch.json
  → 核对 MySQL SUCCEEDED 批次与逐条观测血缘
  → 带 SHA 的输入快照 → HDFS
  → Hive ODS → DWD → DWS → ADS → 导出 TSV
  → Python Decimal 独立对账 → MySQL 安全发布
  → Spring Boot 已发布结果 API → Vue 离线分析与比较
```

关键点是：清洗文件存在，不等于数据库提交成功。`bigdata/warehouse.py` 会把候选文件的完整行集合与成功批次的数据库血缘核对，再建立输入快照。同一个观测可能在多个成功 ETL 批次中出现；ODS 保留这些批次联系，DWD 只计算一次观测，同时保留 batch ID 和 source SHA 数组。因此 JSON、CSV 和重跑文件不会让样本数不断增长。

统计遵守原有口径。时间统一 UTC，窗口采用 `[起始,结束)`；恰好落在结束时刻的记录排除。城市、数据集、版本和 CITY/REGION/ROAD 分开计算。道路所属区域通过道路目录验证，道路观测不会自动转成区域观测。缺失指标由 S5 拒绝，不补成零；没有离线发布时页面明确显示暂无结果。

DWS 保存总和及有效样本数，使 ADS 可以重新计算 `总和÷数量`。例如两个小时分别有三条和一条观测，不能直接平均两个小时的均值。指标和总和使用 DECIMAL，最终均值按 HALF_UP 舍入到两位，Python 也以 Decimal 独立复算。S5 样例的验收目标分别是 CITY 三条观测均速40.00、指数5.00，东区 REGION 两条均速36.00、指数3.00，道路 ROAD 两条均速18.00、指数3.00；这些值仅用于测试断言，没有写进产品查询。

## 为什么发布需要额外的表和事务

不能一边导入 ADS 一边让用户看到半批数据。Flyway 新增 `database/migrations/V4__warehouse_publication.sql`，保留 V1–V3：发布头记录身份和状态，指标表保存每个版本的完整结果，current 表指向当前可见版本。

发布器先核对 Hive、独立计算和 MySQL 回读，再把指标、PUBLISHED 状态和 current 指针放在同一个事务中提交。失败时回滚，旧版本继续可查；同一发布 ID 重试不会重复写指标，换内容则拒绝。规范化内容哈希避免 Hive 输出文件顺序变化造成假差异。后端 `WarehouseRepository.java` 使用一致性读，只查询当前已发布版本。

页面入口是已有城市工作台里的“打开 Hive 离线分析”。`WarehousePanel.vue` 从新 API 获取层级指标、来源、时间窗口和发布版本，并调用已有 MySQL 统计 API 获取相同窗口的 CITY 结果作比较。离线快照与历史观测统计分别标明，后续 ETL 提交可能使两者不同。OpenAPI、Java DTO 和 TypeScript 类型同步定义在工程内，前端没有静态 KPI，也没有提前实现预测或权限系统。

## 可以怎样向老师介绍

可以先打开 S5 成功批次报告，说明为什么必须核对提交状态和血缘；再展示 HDFS 上传/下载哈希、Hive SQL 及四层控制总数，解释跨批去重和总和/数量复算；接着展示一次失败发布仍保留旧版本的数据库记录；最后打开 Vue 离线入口，对照相同窗口的 MySQL 查询。

完整验证入口是 `scripts/s6_checks.py` 和 `.github/workflows/s6-warehouse.yml`，原始执行日志、对账 JSON 与截图由 CI 保存并在 S6 报告索引。Windows 的 `--admission-only` 只验证准入与独立计算，不作为 Hive 实算证据。讲解时要区分“真实运行的技术链路”和“合成测试数据”，也要说明当前验证为隔离单节点环境，后续生产部署和多节点性能仍需单独授权与验收。
