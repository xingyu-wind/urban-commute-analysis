| B 四层数仓 | `bigdata/warehouse.py` 核验 S5 SUCCEEDED 及完整逐条血缘；`bigdata/sql/warehouse.hql` 实算 ODS/DWD/DWS/ADS；独立 Python Decimal oracle 不参与填充 Hive 聚合表 |
| C 发布与系统集成 | 新增 Flyway V4；发布头/明细/current 指针；发布命名锁、SHA/逐行对账、事务切换；Warehouse DTO/Repository/Controller、OpenAPI1.2.0、TS 校验器及 Vue 离线比较入口 |

输入是通过真实 S5 CLI 成功提交的 `normalized.json`、`source.json`、`batch.json`，不是直接把仓库候选清洗结果当成已落库数据。一个 MySQL repeatable-read 快照中检查实际 SUCCEEDED、来源哈希/配置、登记版本/来源和候选完整行集合与 etl_batch_observation 所关联观测完全一致。输入目录和批次不能重复，文件不能静默覆盖。HDFS 输入包保留标准化值、批次、source SHA、版本、观测 ID、道路目录区域、文件 SHA 和 SQL SHA；全部数据为 synthetic_test。

ODS 保留跨批血缘。DWD 按观测唯一身份去重、保留 batch_ids/source_hashes，并按 UTC 日期分区；SQL 额外断言字段约束和唯一性。DWS 按城市、数据集/版本/来源、层级、目标及 UTC 小时分别保存样本数、速度总和、拥堵总和与时间覆盖。ADS 从这些总和/数量生成 HOUR、DAY、WINDOW；每种粒度均覆盖相同输入，不能把三种粒度的样本数相加。

窗口是 UTC `[from,to)`；日/小时桶对部分窗口只描述窗口内观测。速度 DECIMAL(6,2)、拥堵 DECIMAL(4,2)、总和 DECIMAL(24,2)，只在最终 SUM/COUNT 后 HALF_UP 到两位，不平均分区均值。S5 缺失指标拒绝，数仓不补零；CITY/REGION/ROAD 不混合，ROAD 原始 region_id 仍为 null，目录区域经同城道路关系核验后单独保留。跨城市/数据集的控制总和只用于审计，产品指标始终分组查询。

V4 新增 warehouse_release、warehouse_metric、warehouse_current，V1–V3 原文保持不变。发布先对所有 Hive 行、样本数、总和、均值、唯一性、覆盖范围及输入 SHA 独立对账，再核对目标库批次身份。STAGING 头可持久化；指标插入、完整 MySQL 回读、PUBLISHED 状态及 current 指针在同一事务中提交。异常回滚明细与指针，失败头为 FAILED，旧发布继续可查；进程中断可留下 STAGING，由下一发布锁持有者安全重试。

同一发布 ID 绑定输入清单和规范化 ADS 内容哈希；Hive 物理行顺序变化不会造成重复发布。相同 ID 换身份拒绝；旧快照不能替换较新快照；重放旧成功 ID 返回 reused，不倒退当前指针。发布失败后的重试不增加重复明细。

`GET /api/v1/warehouse/metrics` 只读取 current JOIN PUBLISHED，并在一次 repeatable-read 中取得发布头及明细。参数为 cityId、可选 datasetId 和 WINDOW/DAY/HOUR；未知/重复/非法参数及请求体拒绝。返回来源、发布/数据版本、UTC 窗口、发布时间、成功批次/源 SHA、内容 SHA 和带总和的指标；无发布时 release=null/items=[]，不制造零 KPI。单次最多10000行，超过拒绝。

Vue 城市工作台新增“打开 Hive 离线分析”，显示分层结果、来源、版本和窗口，并使用同窗口调用既有 MySQL CITY 历史观测统计作比较。页面数据全部来自真实 API；原有 S4 工作台和统计接口保留，无 Mock、静态 KPI、预测或权限系统。OpenAPI、Java DTO 与 TS 类型/运行时检查同步。

schematool -dbType derby -initSchema
